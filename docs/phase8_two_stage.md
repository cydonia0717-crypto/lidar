# 第八阶段：双阶段候选动作序列搜索

## 本阶段为什么不再继续调权重

第六阶段无严格安全后备时进行风险排序，6组配对实验新方法成功0次且增加碰撞；第七阶段将停车终端净空作为软评分项，成功率与旧方法相同，弱制动下一次超时还变成碰撞。两者都没有实证支持。

原规划器用一组恒定目标速度与转角外推3秒，然后执行约0.4秒再制动。**在行人横穿、骑行者相遇的场景中，单组动作不能表示先让行、后绕行、再停车的组合。**因此改动作表示，而不是在现有动作表示下不断堆加惩罚项。

## 两阶段搜索的具体实现

假设控制延迟 d=0.25s，第一段候选动作执行0.4s，第二段候选执行1.0s，然后物理刹停、保持静止6s。

1. 基于已经发送并且不可撤回的指令队列计算延迟前缀；
2. 第一段从同样的25组候选速度/前轮转角中选择；
3. 第二段可选保持第一段指令、将速度降为0、维持前轮转角加速、以中速回正、以中速反向转向等，能够表达有限的“减速→绕行”序列；
4. 每个阶段应用与真实车辆仿真相同的最大加/减速度、轴距、最大转角及转角变化速度；
5. 对延迟前缀、第一段、第二段、全物理刹停及停后6s **逐阶段执行动态目标时空碰撞和道路硬约束检查**，任一不满足就拒绝动作序列；
6. 可行序列使用原有路线偏差、进度、方向与净空加权成本，再加入两个动作切换代价；优化变量是\((v_1,\delta_1,v_2,\delta_2)\)；
7. 只把当前最优序列的**第一段控制**发送给底盘；下一控制周期重新选择。这是滚动规划，原第二段并未强制执行，因此**不能宣称递归可行或形式化安全保证**。

与旧方法的公平对照：同一世界、同一CV动态目标、同一车辆约束、同一控制延迟、同一保守圆形碰撞包络和6s停后检查，只改变可搜索动作序列的结构与动作评分时域。运行耗时是必须报告的额外成本。

## 现阶段局限

- 使用的是**理想的合成CV运动目标真值**，尚未接入三维激光雷达带噪观测、漏检、Hungarian匹配或Kalman状态估计；
- 动态目标假设匀速，尚无突然转向/停走等模型失配压力；
- 车体仍以覆盖矩形的圆形包络代替真实Ackermann车身碰撞多边形；
- 有限集合搜索不能保证找到连续动作空间中的全局最优解；
- 规划未来第二段动作未必执行，不能将多阶段终端停驻安全等价于闭环永久安全；
- 计算复杂度增加，必须评价平均/尾部规划时间是否满足目标硬件的控制周期。
