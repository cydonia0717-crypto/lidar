# 第六阶段：无可验证停车后备方案时的风险排序退化（实验性）

## 研究背景与故障实证

在第五阶段双目标真实数值复现中，一些小车在10–12s后进入\`emergency_brake\`，刹停约数秒后骑行者到达停车位置发生碰撞。\`braking_hold\` 给刹停后增加6s预测占据检查，虽有时减少碰撞，但会把碰撞转换成超时；说明扩大硬约束本身没有解决“无动作可行时怎么办”。

这是对**候选动作决策层**的修改，不增加AI或感知模型，也不把物理安全条件取消后冒称算法安全。

## 新增的独立 \`recovery\` 模式

正常决策与\`braking_hold\`一致：使用相同的道路边界、预测障碍物、控制延迟、候选轨迹、实际刹停及停后6秒占据约束；存在完整后备可行候选时，依然以同一代价函数选最优动作。

**仅当无完整后备可行候选时**才启动风险排序退化：

1. 对25组相同速度、前轮转角候选，模拟已发送指令的不可撤销延迟前缀，以及候选动作最初0.4s的可实际执行轨迹；
2. 对任何在此**真正短期执行区间**发生碰撞/越界的候选动作严格排除；
3. 对余下候选，同时分析3秒名义轨迹与“制动至零+停后6秒”的未来占据冲突；
4. 优先考虑3秒名义轨迹不存在碰撞的动作；再依次比较未来相交穿透深度平方乘时间的积分、最早风险出现时间和剩余净空；目标函数成本仅作为最后的平局决胜项；
5. 输出明确标志：\`unsafe_fallback=1\`、\`fallback_strategy=risk_ranked_no_backup\`，并记录候选数及预测违规暴露积分。**这不是安全约束放松后的可证明安全解**：未来仍可能发生碰撞，且没有任何可验证安全动作时应承认此事实。
6. 如果连短期执行安全条件都不满足，则仅请求受控制延迟与最大制动减速度限制的\`emergency_brake\`，不能声称避碰得到保证。

**风险计算** 使用同一车辆保守包围圆与道路模型的*签名净空距离* \(c(t)\)；目标是尽量减小 \(R=\int \max(0,-c(t))^2dt\)。这只是有限确定性模型中碰撞风险的代理量，**不等于概率、不能当成碰撞概率**。对名义轨迹和刹车停驻轨迹分别计算，两者总风险作为退化选择依据，不在已通过验证的正常可行集上影响优化结果。
