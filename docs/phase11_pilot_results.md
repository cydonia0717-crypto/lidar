# 第十一阶段真实实验结果：有向矩形道路模型消除部分轨迹死锁

## 数据与运行方式

[GitHub Actions Run 39220207696](https://github.com/cydonia0717-crypto/lidar/actions/runs/39220207696)；**66项测试通过**。本报告的所有成功率、碰撞、耗时数据均来自 GitHub Actions 实际数值积分日志与\`episodes.csv\`，不是人工预设结果。完整 artifact 包含 \`road-geometry-known/\`、\`road-geometry-holdout/\` 和独立的几何姿态检查报告。

**公平比较**：\`two_stage\` 使用传统车身包围圆规划道路边界；\`two_stage_rectroad\` 用同一车长1.9m×车宽0.85m按航向旋转的矩形规划道路边界。两方法所有闭环仿真采用**相同 oriented rectangle 作为物理越界真值**，保留原0.2m路界安全余量；对动态障碍物仍采用相同外接圆、理想CV预测、同一车辆运动学、两段动作集合/时长、控制延迟和制动约束。没有在物理真值上对旧算法采用更严苛模型。旧算法原始历史基线使用圆作为物理道路模型，但**本报告所有对照回合都统一改为矩形物理判据重跑**，避免不公平。

## 三、计算成本

| 工况 | 旧（毫秒） | 新（毫秒） |
|---|---:|---:|
| 已知 nominal | 36.825 | 48.109 |
| 已知 weak_brake | 37.224 | 46.860 |

四组均值的简单平均约 **31.58ms → 41.80ms**，开销约增加**32%**；这是不同回合长度与负载的描述性均值，不是严格实时调度测量。原有旧方法只探索圆形硬约束，候选早期被拒绝，允许更多实际有效的轨迹后需要评估更多后续动作，因此计算开销增大符合算法路径特征。

## 四、为什么仍不能宣称论文创新已经得到证明

1. 包围圆→有向矩形是已知、标准的机器人碰撞几何精细化方法，不能称为全新算法本身。硕士论文若要构成研究贡献，需要与**延迟感知双阶段轨迹决策、停驻后备可行性和可恢复性验证**相结合，进行可靠消融。
2. 运动目标是**仿真真值匀速CV**，没有雷达点云、漏检、目标关联、突然变速/转向；测试场景仅数个固定人工模板。
3. 车辆状态原来使用中心模型，真实阿克曼后轴参考点/车体中心偏置未标定，矩形投影是假设车体中心在\`(x,y)\`；真实车辆可能需要修正车体质心/后轴坐标变换。
4. 动态目标碰撞仍用保守外包圆，只有**道路检查**变成有向矩形；与车辆、道路相关的离散运动采样不能保证连续时空碰撞严格安全。
5. 不应该为了通过已知0、1、10、11四组种子继续调几何或权重。必须加入从未参与设计的窄路、横穿速度扰动与多目标参数新场景，区分训练/留出数据。

**下一步**：检查其它场景与窄道路下是否出现新增道路越界、动态碰撞或计算不可用情况；再引入精确车辆参考点与轨迹边缘恢复能力。

额外场景均使用相同物理矩形作为道路越界真实判据、相同车辆参数和CV目标仿真、同样的制动/延迟与障碍物包围圆。只改变道路规划时的几何近似。

### 当前累计描述性结果

- 双目标：8对实验，旧包围圆规划2成功、1碰撞、5超时；新矩形道路规划7成功、1碰撞、0超时；
- 其它三场景：6对实验，旧规划6成功、新规划6成功，均没有碰撞和超时；
- **总计14组配对**：旧规划 **8/14成功、1/14碰撞、5/14超时**；新规划 **13/14成功、1/14碰撞、0/14超时**。均无实际道路越界。

限制特别说明：同一场景、相近种子和理想CV目标不构成来自真实人群运动的独立抽样；两组制动工况也复用相同随机几何。不能将累计比例当论文推断统计的独立大样本效果，更不能说“修正道路几何使所有运动场景安全”。

研究价值应描述为：**通过逐级归因定位固定包围圆导致的道路可行空间保守缩减，并在同一车体物理模型及其它轨迹约束下验证几何精细化能避免特定阿克曼两阶段规划死锁，同时报告计算成本与失败回合。** 矩形几何本身是成熟常见方法，需要与多阶段控制、车辆状态与安全备选轨迹的可行性研究组合，才可支撑论文贡献。
