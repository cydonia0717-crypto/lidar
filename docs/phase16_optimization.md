# 第16阶段：可恢复性决策的计算优化与严格等价审计

> **状态：研究分支实验，尚待完整配对 CI 验收；不能以此宣称 Jetson 已满足 10 Hz 实时控制。**

## 1. 固定研究口径

基础分支来自 [PR #15](https://github.com/cydonia0717-crypto/lidar/pull/15) 的固定提交
`7676ced92e27c479c577de3e33e0f190c07f8031`。**不更改**阿克曼运动学、
后轴至车身中心 0.55 m、车长 1.9 m/宽 0.85 m、路界有向矩形、CV 动态目标、
0.25 s 指令执行延迟、完整物理制动、停车后 6 s 占据检查、`pose_gate`
及 100 ms 仿真控制周期。

对照分为三个**不同概念**：

- `two_stage_bodyframe`：没有未来可行性前瞻的严格双阶段决策算法，对应论文方法消融基线；
- `two_stage_viability_phase15`：第15阶段冻结的原始前瞻规则，保留最多 3 个候选完整探测和 `forced_first` 重跑；用于第16阶段**实现等价性与计算开销**审计；
- `two_stage_viability`：第16阶段仅优化计算流程的前瞻规则。若动作不同，视为需要调查的实现偏差，而非预期创新。

## 2. 已实现的三个计算优化

1. **有序前瞻提前停止。** 先按原代价严格排序。原实现最终选第一个存在安全续接的候选；因此找到首个合格候选后，继续探测次优候选不会改变输出动作。明确输出 `lookahead_unprobed`，并不把未探测候选标成不可行。
2. **父规划完整轨迹复用。** 完成所有原硬检查后，记录每个第一段动作对应的最佳第二阶段、制动、停车完整轨迹和原评分；找到不同第一段动作时，从同一次父节点规划取得已验证结果，不再运行 `forced_first`。
3. **子规划只找严格可行见证。** 对下一状态的父动作-第二动作进行原五阶段的完全相同硬检查，发现第一对全部通过的动作后立即返回 `True`。不再为了存在性判断计算其余候选评分和全部可行组合。**只保证布尔存在性等价，不能声称保留原子规划的精确可行组合数量。** 日志使用 `lookahead_child_witness` 与 `lookahead_child_count_exact=0` 标明语义。

目前独立测试用 `strict_continuation_exists` 与原 `choose_two_stage` 的可行性布尔值互相对照。应对更多几何与目标状态继续扩展这个审计。独立函数复制了硬约束检查顺序，今后任何运动学、碰撞检查改动都必须同时重新验证一致性。

## 3. 同条件实验与失败即停止的审计

`.github/workflows/phase16.yml` 拟在相同 Runner 上运行：

- `two_targets/weak_brake`：种子 0、1、10、11，35 s 截止；
- `crossing/nominal` 与 `narrow/nominal`：各种子 40，35 s 截止；
- 三种模式均使用相同 `rearaxle_rectangle` 物理车体和 `pose_gate`，保存全部逐周期 CSV；
- `python -m lidar_sim.phase16_equivalence ...`：对冻结 PR15 与 PR16 比较每周期控制命令、实际应用命令、车体状态、安全余量、停车/后备状态与最终结果。任何首个分叉直接使工作流失败。性能墙钟耗时与探测诊断允许不同；
- 输出 `phase16-equivalence.csv`，包括每回合两模式平均耗时、P95/P99、>100ms比例和平均耗时速度比；
- `phase16-timing.csv`：全部模式、全部回合的时限分布；
- `phase16-profile.csv`：优化模式父节点、子节点耗时拆分、子调用次数、提前停止次数、轨迹缓存命中次数。

`phase16_timing` 采用排序样本间线性插值计算 P95/P99。只有真正执行规划的轨迹行记入分位数；终点附加行不得被当作 0 ms。原物理确定性测试需要忽略 `planning_ms` 这一真实 CPU 抖动字段，不得忽略状态或动作偏差。

## 4. 结果填写规则

完成 CI 后从真实 `all_traces` 和生成的 CSV 填写：每回合最终结局、首个状态/动作差异、平均/P95/P99/max、100ms 超时比例、父/子耗时、动作改动次数和缓存命中次数。**没有测量数据时不填写改善倍数或完成率。**

Runner 上两模式顺序运行，受 CPU 调度、热身与共享实例波动影响。单次相同 Runner 的配对计时只能作为探索性性能证据，后续还需重复运行或交错顺序控制系统误差。

## 5. 与下一阶段严格分离

当前 `planning_ms` 只进入日志，不反馈到车辆指令队列。因此第16阶段验证的是**无计算延迟反馈下的动作/轨迹等价性与运行时间**。第17阶段再将实际计算耗时加入物理控制执行时序，不应将第16阶段的无碰撞结果外推到具有计算延迟的实车。
