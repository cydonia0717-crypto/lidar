# 第三阶段：可解释的阿克曼候选动作决策

## 这才是规划器自身的“决策”部分

每个控制周期，根据小车当前状态、目标未来位置和待生效控制指令，采样速度目标 v 和前轮转角 δ（默认 5×5=25 组）。使用运动学自行车模型积分得到候选轨迹 \(\xi_u\)。

### 第一步：先检查硬约束

所有模式需要满足道路边界、目标的时空碰撞约束。braking 模式还要求完整的“延迟前缀 → 候选执行 → 制动尾迹”安全检查。

不满足硬约束的候选动作**不会因代价函数评分低而被接受**。正常情况下在安全候选集内选择最小总代价；没有安全候选时明确标记 unsafe_fallback 或 emergency_brake，不能称作有安全保证。

### 第二步：在允许动作里评价行为好坏

各个可解释的*已加权*成本项：

\[
J(u) = J_{route} + J_{progress} + J_{speed} + J_{steer}
     + J_{heading} + J_{clearance}.
\]

- **路线偏差**：\(J_{route}=w_r \frac{1}{N}\sum_k y_k^2\)。这里道路参考线是 y=0，后续需要替换为一般曲线投影的横向误差。
- **沿线进度**：\(J_{progress}=-w_p \max(0,\min(x_N,x_{goal})-x_0)\)。负号表示鼓励向目标方向前进；只对当前沿x单向道路有效。
- **速度改变**：\(J_{speed}=w_v(v_{target}-v_0)^2\)。
- **前轮转角改变**：\(J_{steer}=w_\delta(\delta_{target}-\delta_0)^2\)。
- **航向偏差**：\(J_{heading}=w_h \frac{1}{N}\sum_k yaw_k^2\)。
- **安全余量偏好**：对于第 k 个状态，计算距道路边界或目标占据区域的最小剩余净空 c_k，\(J_{clearance}=w_c\frac{1}{N}\sum_k[\max(0,c_{target}-c_k)]^2\)。它只是偏好项，不能替代硬碰撞检查。

只要评分权重非负（进度项内部已带负号），数值越小越好。目标权重是可调整的工程超参数，并未证明最优。当前时间序列直接按样本点求平均、未作精确时间积分；后续应检查不同时间步大小对评分的影响。

### 第三步：记录选择理由

运行时每个备选动作记录 v、δ、6个成本项、总成本、状态（正常可行 / 常规碰撞拒绝 / 制动尾迹拒绝 / 选中 / 不具备验证后备但退化执行）。

闭环 trace CSV 记录每个控制周期实际选择动作的成本分项；另输出某一代表时刻**全部25个候选动作**的 CSV 和可视化图。图中的每个圆对应一组候选 v、δ，数字为计算出的总代价，颜色区分硬约束拒绝与决策结果；不是人工绘制的预期效果图。

## CLI 示例

\`\`\`bash
pip install -e '.[dev]'
pytest -q

# 输出轨迹、代价分项、25个候选动作对比图
lidar-sim --scenario crossing --mode braking --seed 0 \
    --decision-figure --plot

# 将安全偏好权重从0.6增加到2.0做敏感性实验
lidar-sim --scenario crossing --mode braking --seed 0 \
    --clearance-weight 2.0 --decision-figure

# 控制其他条件不变，在同一组种子下比较四种决策模式
lidar-sim --scenario two_targets --compare --seeds 10
\`\`\`

当前 reactive 和 predictive 模式的预测附加余量相同；它们主要差别是目标冻结与目标按CV移动预测。braking 在 predictive 和 delay_aware 基础上进一步检查后备停车。

## 为什么还不能称为完成论文创新？

1. 数值仿真直接读取动态目标理想状态，尚未通过模拟雷达噪声/漏检和CV-KF追踪产生估计数据。
2. 道路是沿x轴的直线；到任意RTK曲线的投影和道路走廊尚未实现。
3. 权重是人工选定，仍需要敏感性实验和成功率/碰撞率/通行效率多目标权衡。
4. 安全采用离散包围圆几何，不提供严格连续时间碰撞保证。
5. 三段式制动过滤是否真正改善**最终闭环安全与效率**尚未由足够多独立场景和随机种子得到支持。

阶段目标：明确算法输入、决策变量、优化目标、约束条件和可复现的选择理由；下一步让物理制动约束产生可测量的独立贡献。
