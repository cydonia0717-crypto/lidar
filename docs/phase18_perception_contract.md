# 第18阶段准备工作：LiDAR 跟踪结果 → 局部规划器的只读影子回放契约

> **范围**：先在离线输入上验证“时间戳、坐标系、已执行动作队列、动态目标估计”是否能正确进入第16阶段已冻结的局部规划器。**尚未接入 ROS 订阅者、真实录制数据、目标预测校准、实车控制或碰撞统计。**

## 为什么先做接口，而不是继续改避障算法

第15阶段的未来可行性过滤、第16阶段的效率优化都基于 `World` 中准确的障碍物CV状态。此前真实ROS/RTK/感知项目中的激光雷达点簇、轨迹编号、KF估计并没有集成进本研究仓库。真实跟踪数据有不同的观测时间、漏检和外参；不能简单把 `MovingObstacle` 改名叫“LiDAR障碍物”就称为感知验证。

本迭代故意**不修改第15—17阶段规划器**，也不引入新的权重或AI模型。新增 `src/lidar_sim/tracked_shadow.py` 接收一个JSONL：每行是一个当前估计状态的**只读快照**，每个快照独立提供规划器完整所需信息。

## 数据契约（每一行均为完整JSON对象）

~~~json
{
  "t_s": 12.50,
  "frame": "odom",
  "ego": {
    "x_m": 5.1, "y_m": 0.1, "yaw_rad": 0.03,
    "speed_mps": 0.6, "steer_rad": 0.01
  },
  "road": {
    "half_width_m": 3.25, "goal_x_m": 28.0,
    "safety_margin_m": 0.20
  },
  "actuator": {
    "delay_s": 0.25,
    "active": {
      "target_speed_mps": 0.6, "target_steer_rad": 0.01
    },
    "pending": [
      {
        "activate_at_s": 12.68,
        "target_speed_mps": 0.0,
        "target_steer_rad": 0.01
      }
    ]
  },
  "tracks": [
    {
      "id": "track_7",
      "observed_at_s": 12.40,
      "x_m": 13.1, "y_m": -3.8,
      "vx_mps": -0.1, "vy_mps": 0.4,
      "radius_m": 0.45,
      "point_count": 12,
      "sigma_x_m": 0.15,
      "sigma_y_m": 0.20
    }
  ]
}
~~~

**坐标与时间规则：**

- `odom` 是固定平面局部坐标系；自车位置须为**后轴中心**，`yaw_rad` 为该坐标系下航向。路线暂仍假设+x方向的**直线走廊**；弯曲RTK路线、地理坐标以及地图本体不在本次支持范围内。不能传 `base_link` 等随车旋转的坐标系冒充 `odom`。
- 所有时间 `t_s`、`observed_at_s`、`activate_at_s` 都在同一个时钟基准内，秒为单位；不可把ROS header相对时间、墙钟Unix时间和 `bag` 回放时间混用。JSONL时刻必须严格递增，缺失超过 `--max-gap` 的时段会标记为**不给建议**。
- 一个目标的 `x_m, y_m` 是**在 observed_at_s 时刻的估计值**，不是在规划时刻的真值。适配器用 `x(t)=x_obs+v_x(t-t_obs)` 在绝对时间轴上生成CV预测。目标编号不得重复；当前的目标状态、速度和时间戳来自上游跟踪器，不应将仿真真值作为线上输入。
- `radius_m` 是上游给出的目标保守几何半径假设；`sigma_x_m`/`sigma_y_m`、点数是保留的质量元数据，**本版本并未完成整段预测误差校准，也没有把标准差自动映射成安全概率包络**。不能据此说不确定性已解决。
- 必须提供实际正在生效的 `active` 和完整未到时的 `pending` 命令列表；如果只有历史 `/cmd_vel` 而没有执行器实际生效时序，不能默默假设pending为空。完整队列应由底盘命令记录和经验证的执行延时构建，否则影子计算的延迟前缀缺乏物理依据。
- `ego.steer_rad` 指实际前轮转角状态，`active.target_steer_rad` 是当前生效目标；它们不能直接从ROS `angular.z` 猜算，必须确认底盘接口和轴距/转向映射。
- 不支持障碍完全遮挡后首次进入可见区的形式化安全保证，也没有“探测范围外必为空”的证据。本迭代仅针对当前有可信已跟踪目标的时刻。

## 明确拒绝的不安全假设

| 输入状态 | 本接口结果 |
|---|---|
| 目标最近观测超过0.35s（可设置） | `stale_track_estimates`，不调用规划器 |
| `tracks=[]` | `no_observed_tracks_unverified_free_space`，**不能默认为无障碍场景** |
| 缺失执行器待生效指令队列 | 输入错误，拒绝推测 |
| 混入`base_link`或其它坐标系 | 输入错误 |
| 目标观测时间在决策时刻之后、目标ID重复、非有限数字 | 输入错误 |
| JSONL出现长期时间缺口 | `timestamp_gap_no_recommendation` |
| 规划器本身无严格后备可行解 | `unsafe_fallback_no_guaranteed_action`，不把零速请求当作安全停车证明 |

这些都是**影子模式**标记，**并不自动向车辆发送停车命令**。实车系统仍须具有独立安全看门狗、失效降级和人工急停机制；影子模式不能替代安全层。

## 用法与数据来源

~~~bash
python -m pip install -e '.[dev]'
python -m pytest -q tests/test_tracked_shadow.py
python -m lidar_sim.tracked_shadow \
  --input tests/fixtures/tracked_shadow_synthetic.jsonl \
  --output results/tracked-shadow-demo.csv \
  --max-track-age 0.35 --max-gap 0.5
~~~

**注意**：仓库内 `tracked_shadow_synthetic.jsonl` 特别标记为合成示例，不是ROS bag、点云检测结果、RTK实车轨迹。输出只是输入状态对应的“规划器建议、无安全证明状态和耗时”，**不能当作闭环成功率或实际障碍跟踪准确率**。该模式不前推车辆、不更新障碍真值、不发布 `/cmd_vel`。

## 与历史ROS工程如何衔接

已有室外平台历史工作包括RTK与参考路径追踪、LiDAR聚类、跨帧目标关联、CV Kalman、独立命令看门狗等；但这些代码目前**没有**在本研究仓库中。下一步先从真实静态、行人横穿及短时丢检的ROS bag中导出以下字段：里程计基准姿态、目标ID/位置/速度/尺寸、观测与规划时戳、底盘当前命令及已排队的激活时刻。不得靠ROS bag的历史ego轨迹“回放”出反事实避障成功率——影子回放只能回答在所记录的当下状态算法会**建议什么**。

**建议的最小真实数据验收顺序：**

1. 静态物体日志：姿态修正后估计目标速度是否近零，输入时戳/坐标是否对齐。
2. 已标注横穿行人：不同距离、点数、丢检下检查 `age_s`、轨迹ID连续性及0.5/1.0/2.0s预测残差（需要独立参考观测）。
3. 同一bag中原第16阶段规划器影子执行：记录每帧可行候选、降级原因、CPU耗时与当前车辆状态，**不发送控制指令**。
4. 用独立数据构造有限时域预测包络，比较固定余量、统一校准、分组校准的整段覆盖率—面积权衡。不能只在合成数据上调安全膨胀参数。
5. 完成真实车体偏置、轴距、转向响应、制动距离、执行时延标定，并确认之前假设的0.25s是否包含规划CPU时间。

完成这5步之前，不进入无人监督的实车横向绕行测试。论文当前可称“LiDAR跟踪数据到规划器的接口契约与只读回放”，不能称“激光雷达闭环避障系统已集成”。
