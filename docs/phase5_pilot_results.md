# 第五阶段：停车后占据检查的先导实验（真实数值运行记录）

## 数据来源

[GitHub Actions 工作流 39192137105](https://github.com/cydonia0717-crypto/lidar/actions/runs/39192137105)；运行时的完整 CSV 和图保存在 artifacts。此数据由原代码实际数值积分得到，不是人工挑选的预期指标或实车结果。

- 场景：\`two_targets\`
- 压力：\`nominal\` 和 \`weak_brake\`
- 每种工况使用种子0、1、2
- 对照：\`braking\`（直到停车为止）与 \`braking_hold\`（在停车之后继续检查6秒静止占据）
- **6组配对回合、12次实际闭环仿真**。两种方法使用完全相同的目标初始位置、CV速度、道路边界、车辆参数和指令延迟。

## GitHub Actions 实测先导统计

| 工况 | 模式 | 成功 | 碰撞 | 成功回合的平均完成时间 |
|---|---|---:|---:|---:|
| nominal | braking | 1/3 | 2/3 | 15.0秒 |
| nominal | braking_hold | 1/3 | 2/3 | 17.4秒 |
| weak_brake | braking | 1/3 | 2/3 | 14.9秒 |
| weak_brake | braking_hold | 1/3 | 1/3 | 17.8秒 |

**结论有两个约束：**

1. 在上述六组配对样本中，\`braking_hold\` 没有提高任务成功率；单一压力工况仅3个样本，统计不稳定，不能推断“安全性提高XX%”。
2. 弱制动压力下碰撞少了一次，但是**不是多完成了一次任务**。需要检查新模式中余下失败是超时还是道路越界，并且解释安全—效率的权衡；后续代码额外导出每个配对案例的 \`collision/timeout/road_exit\` 及代价变化，避免只报碰撞率。

三个重要限制：
- 运动目标来自理想的合成CV轨迹，不含雷达点云噪声、漏检或者关联错误；
- 车体是包围圆，碰撞为离散时间样本，不能推出连续时空安全保证；
- 停车后6秒的占据检查是**有限条件**，并不保证目标后来不加速、不转向或不会撞上停车车辆。

## 改进后自动输出

- \`episodes.csv\`：所有单回合，包含成功、碰撞、越界、超时；
- \`summary_by_scenario_stress_mode.csv\`：按场景与模式统计四种独立结局，完成时间仅统计成功回合；
- \`paired_post_stop_effects.csv\`：逐个相同种子对比 \`braking_hold-braking\` 的完成/碰撞/超时/越界变化，明确区分“少碰撞但仍未完成任务”和“真正更安全更高效”；
- \`rates_by_stress.png\`：实际成功率与碰撞率，可参考但不代表显著性。

当前更值得研究的是**小车为何会陷入无可行候选动作以及如何提前避免死锁**，而非继续把停车检查时域无限延长。
