# 第二阶段：延迟感知的候选动作—制动尾迹可行性筛选

> 状态：数值仿真原型；未使用真实雷达数据，不具备概率或形式化安全保证。

## 方法与动机

原始候选轨迹 (目标速度 v、前轮转角 δ) 的预测碰撞检查，并不能证明底盘执行延迟和动力学限制下还存在安全停车路径。此模块用相同的执行模型预测三段运动，拒绝制动尾迹和道路边界/移动目标冲突的候选动作。

1. **延迟前缀**：在 t 至 t+d 继续执行已经生效及队列内已发送、尚未生效的历史指令。仿真积分切分在每个队列事件处。
2. **候选执行段**：t+d 至 t+d+T_exec，执行候选速度与前轮转角；受速度、加减速和转向变化率限制。
3. **制动尾迹**：从上一步的实际运动状态开始，速度目标设为 0，保持该时刻的实际前轮转角，按可实现的最大减速度推演至车速为零。

运动学自行车模型：

- dx/dt = v cos(yaw)
- dy/dt = v sin(yaw)
- dyaw/dt = v tan(steer)/wheelbase
- 加减速与前轮转角变化率受到 VehicleConfig 的物理限幅。

当前设置：控制延迟 0.25s、候选执行窗口 0.40s、制动减速度 1.6 m/s²、制动碰撞采样 0.05s；以上均为**演示假设值**。车辆是覆盖整车矩形的保守圆，动态障碍物是移动圆。安全判据为圆距离不小于车辆半径+目标半径+预设路况安全余量+预测附加余量，且车体不会超出允许道路边界。

没有处理采样间隔内的连续碰撞，没有真实点云跟踪输入，没有经过独立数据校准的预测误差包络，也没有控制延迟或制动减速度的实车标定。停止后的动态目标碰撞同样未能保证避免。

## 可公平复现的几种消融模式

- reactive：冻结障碍物当前的位置（弱基线），规划不显式考虑指令延迟。
- predictive：使用移动障碍物CV未来位置，但规划假设指令可以立即生效。
- delay_aware：预测中加入当前待执行指令队列，但不要求完整制动尾迹避碰。
- braking：delay_aware 之外，进一步验证“延迟前缀 + 候选执行 + 完整制动尾迹”。

**实际车辆仿真在以上四个模式中使用同一延迟模型**；非 reactive 三种模式也使用同一预设预测附加余量。仍需要扩展场景、校准观测模型后才能讨论正式论文统计差异。

## 重要失败工况

late_crossing 场景中，继续前行有可能不会与横穿目标相撞，而原地制动却可能恰好停在目标经过的位置。制动过滤器能够发现某些候选动作的后备制动尾迹不安全，但若全部后备方案均不可行，也不能简单假设“急刹必然安全”。

实现的显式退化策略：
- 若全部后备方案不满足要求，但仍有常规预测下不碰撞的轨迹，则选择其中代价最低者，打标 unsafe_fallback=1、fallback_strategy=nominal_no_backup。
- 若常规预测也找不到可行轨迹，则提出速度目标0的物理制动请求，打标 unsafe_fallback=1、fallback_strategy=emergency_brake。这是失败降级，不构成安全性证明。

上述策略在真实硬件中不能代替硬件紧急停止和安全监督机制。

## 运行

```bash
pip install -e '.[dev]'
pytest -q
lidar-sim --scenario crossing --compare --seeds 10
lidar-sim --scenario two_targets --compare --seeds 10 --control-delay .25 --deceleration 1.6
lidar-sim --scenario late_crossing --mode braking --plot --backup-figure
lidar-sim --scenario crossing --compare --seeds 10 --control-delay .5 --deceleration 1.0
```

查看 results/ 下 CSV、JSON 和 PNG。图像里的三段轨迹来自真实的运动学数值积分，是假设指令的单次前瞻可视化，并非实车数据或已执行轨迹。
