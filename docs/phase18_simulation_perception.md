# 第18阶段：以仿真为主、保留未来实车接入的因果感知闭环

> **目标**：针对2026年10月23日研究路线确认，当前主要以**仿真**验证算法；未来可能使用ROS/实车，但真实数据、真实标定、ROS部署都**不是当前实验先决条件**。

## 为什么新增这一层

第15—17阶段规划器中的动态目标均来自二维真值世界 `World`，其速度和位置在控制器调用前已经完全准确。这个假设使得算法对动态感知误差、丢检、信息陈旧等问题的敏感性无法评价。

本阶段在原 `run()` 增加可选的 `SimulatedPerception` 参数，**不影响未设置此参数的历史oracle回归**：

~~~text
不可变的物理真值 World ─────────────────────────────→ 仿真车辆及碰撞/道路结局
             │
             └→ 根据过去车身位姿、过去目标真实位置生成合成观测
                └→ 距离相关高斯误差 / 随机丢检 / 视野与量程 / 时戳延迟
                   └→ 连续观测估计目标速度（禁止直接读取真值速度）
                      └→ 到当前规划时刻的CV估计 World
                         └→ 原封不动的第16阶段后续可行性规划器
                            └→ 原物理指令延迟队列（仅仿真）
~~~

仿真器独立保留真值，用于未来各时刻的几何碰撞和成功判定。规划器只拿到估计的 `World`。两者使用**同样的道路和车辆几何参数**，模拟地图已知、车辆自定位精确的场景。这里是真值分离，不是概率安全证明。

### 因果性、缺失处理与固定假设

- **观测时刻**：`capture_delay_ticks`定义传感数据按多少个100ms（默认）控制步推迟可用。历史车身位姿用于采样捕获时的视野和测距，不偷看未来的自车轨迹。
- **检测/噪声**：只在目标可被范围/FOV几何访问时生成中心点观测；通过每个episode、tick、目标ID的稳定哈希随机数生成可重现噪声/丢检。`sigma=position_sigma_m+range_sigma_per_m×distance`。这些是明确选择的**合成噪声参数，不是任何具体雷达的测量标定结果**。
- **目标速度**：首次检测目标时速度未知，不能偷用仿真真值；至少有两个不同时间的观测，才从位置差估计速度；之后用平滑系数更新。使用真值目标ID维持关联，这是**oracle data association**，并未模拟目标ID切换、混淆或误检，必须列为模型局限。
- **旧轨迹**：未在本次检测到的旧轨迹在 `max_track_age_s`内使用已有估计外推；超过该时间的旧轨迹触发`stale_tracks_unresolved`，整个规划时刻进入请求制动后备。完全没有有效轨迹时触发`uninitialized_or_no_tracks`；绝不把缺失目标自动转成自由空间。
- **闭环真实动力学**：`experiment.run`仍用真值 `World` 和已有延迟队列积分底盘、计算碰撞；`perception`只进入`choose_action`输入。无可靠感知时指令为目标速度0，但由于执行时延和制动能力，**这不保证立即停车，更不保证停车后免于被动态目标碰撞**。
- **配置隔离**：一个感知配置用于一个回合、一个规划器；相同物理case使用相同观测随机种子。若规划器产生不同车辆轨迹，其历史自车位置可能改变后续测距/可见性，因此**不能假装完全相同的观测序列在所有规划器间总成立**。若研究仅感知规划本身，可增加离线固定观测带作为进一步严格匹配实验。
- **映射到未来实车**：估计目标数据使用与PR #20`tracked_shadow.py`同类的时间锚点`MovingObstacle.reference_time_s`、局部odom坐标、目标位置、速度、半径。未来只替换上游观测来源和标定参数；道路真实几何、执行器队列、自运动补偿、目标数据关联与点云前端需要重新校准验证。当前绝无ROS控制输出。

## 对照实验

~~~bash
python -m pip install -e '.[dev]'
python -m pytest -q tests/test_simulated_perception.py tests/test_phase18_sim_eval.py

# 独立case按相同物理世界、相同障碍物运动、固定seed比较
python -m lidar_sim.phase18_sim_eval \
  --scenarios crossing,two_targets --stress weak_brake \
  --seed-start 0 --seeds 4 \
  --modes two_stage_bodyframe,two_stage_viability \
  --profiles oracle,clean,noisy,degraded \
  --max-time 35 \
  --output results/phase18-sensing-ablation
~~~

profile定义：

| profile | 目标中心测量误差 | 丢检概率 | 捕获滞后 | 使用方式 |
|---|---|---|---|---|
| `oracle` | 0，直接CV真值速度 | 0 | 0 | 历史第15—17阶段控制上限；**非因果感知** |
| `clean` | 0，不提前给真值速度 | 0 | 0 | 因果跟踪与初始化本身的对照 |
| `noisy` | 0.08m + 0.003×距离 | 5% | 1个控制tick | 一种设定的轻度合成退化 |
| `degraded` | 0.16m + 0.01×距离 | 25% | 2个控制tick | 一种设定的强合成退化 |

所有profile默认的观测最大龄期为0.35秒（可在代码中调整），限制作用在每条轨迹的最新观测时戳上。输出`episodes.csv`、`inputs.json`及每回合完整`_metrics.json`/`_trace.csv`。追踪`perception_enabled`、`perception_blocked_steps`、`perception_planned_steps`、`perception_detection_events`以及每次决策的检测数、有效轨迹数、轨迹龄期、降级原因。另有只作**离线评价**的 `perception_eval_mean_position_error_m`、`perception_eval_mean_velocity_error_mps`：这两项在规划完成后才与仿真真值比对，不会反馈给规划器；仅统计有有效轨迹的时刻，漏检/阻断次数需单独报告，不能把有检测时的误差等同总体感知质量。完整物理结局仍计入原碰撞、道路越界、超时和成功指标，不允许把停车超时称为避障成功。

**小规模CI仅做smoke**：运行时长为0.4秒，只证明程序能够按正确口径写出结果；这绝非统计显著的实验。30～35秒完整实验在论文中必须包含独立种子、困难场景、配对状态解释、误差条/区间、样本量、失败归因和运行耗时。特别注意第17阶段`measured` CPU反馈结果与GitHub Runner负载有关，不可在不同Runner间直接作为安全效果对照。这里各profile共用已有**固定0.25s传输延迟**，模拟感知延迟另行加入，不应把这种设置解释为实车标定。

## 尚未实现的感知研究和外推边界

1. **目前不是3D激光点云仿真**：没有光束射线追踪、地面分割、物体自遮挡、反射强度、车体外参、点簇宽度/点数、多目标数据关联、假阳性或真实ROS消息；当前是2D目标中心的**LiDAR-like受控观测模型**。
2. **H1未完成**：仅引入可配置噪声/漏检和因果速度估计，还没有实证比较分组校准安全包络与固定安全余量的完整碰撞—效率收益；上一轮PR #21的预测误差评价器可复用于合成独立观测/真值分离条件，但应由独立种子回合建立校准和测试集。
3. **H2也需再验证**：前瞻规划器在理想观测下的优势不一定能迁移到退化观测，需检查弱制动/双目标中是否出现假安全轨迹、过度等待或回退触发；不能仅用4/4困难场景总结成功率。
4. **实车迁移**：后续若返回实车，先从已验收的只读影子接口、ROS1 Noetic时间/坐标检查、真实车体和制动标定及独立看门狗开始；将合成观测替换为真实跟踪器输出。**现在不要求用户采集bag，也不因此停下仿真研究。**


### CI的单场景诊断（区别于统计性实验）

除0.4秒smoke之外，专用CI额外运行 `two_targets/weak_brake/seed0`，分别针对原两阶段和优化前瞻，在`oracle/clean/noisy/degraded`四种观测配置下各运行最多22秒（8回合）。保存每回合的原始轨迹和物理结局，以便确认噪声是否改变控制行为，并检查是否出现停车后被目标侵入。**该种子属于已知困难案例；8回合不是8个独立种子，不得据此宣称某种算法对噪声有普遍鲁棒性。** 完整实验未来还需使用开发/测试种子隔离和分场景统计。
