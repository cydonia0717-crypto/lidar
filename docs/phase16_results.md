## 实现和判据

旧\`two_stage_viability\`为每个最多3个原代价最优的严格可行第一段动作，分别在0.60s未来状态运行完整\`choose_two_stage\`：枚举并评分所有符合连续两段动作、道路、目标碰撞、物理制动尾迹和停后6s占据的方案。新的\`two_stage_viability_fast\`**完全保留**旧规划器选中的首段动作，只用等价存在性判据\`exists_strict_continuation\`找到一条合规续接即短路，且一旦按原成本顺序找到第一个有可行续接的候选，停止探测更高成本候选。若无可行续接，退回原旧基础安全动作。**没有缩小车辆宽长、删除碰撞判据或放宽安全余量、控制延迟和制动参数。**

二者\`lookahead_child_feasible_count\`解释不同：快版报告值1代表“至少有1个严格可行的未来续接”（布尔证据），不是未来组合的精确数量。新增\`lookahead_child_count_is_witness\`标记此口径。

## 完整实验设计

物理真值\`rearaxle_rectangle\`，车辆后轴至车身中心偏置\`0.55m\`（仍是**未经测量**的假设），真实车长1.9m、宽0.85m，阿克曼自行车动力学，同一CV运动目标真值、同一道路半宽、同一0.25s执行延迟；双目标弱制动力0.9m/s²，普通工况制动力1.6m/s²；\`pose_gate\`要求车体几何中心过目标线、横向误差≤0.75m、航向误差≤15°，时限35秒。

- 已知双目标弱制动seed0,1（第十四阶段追踪过失效）；
- 前期已使用的双目标弱制动seed10,11（不能称为全课题独立测试集）；
- 之前**未参与设计**的seed50,51，\`crossing/narrow/two_targets\`×\`nominal/fast_targets\`共12组不同模板、目标速度压力。

**16组×2种模式**，严格逐帧验证\`time,x,y,yaw,speed,steer,command_speed,command_steer,applied_speed,applied_steer,body_center_x,body_center_y,pose_gate_met\`的数值误差不超过1e-8，同时要求行数一致。所有16组通过；没有使用“成功率相同”来代替控制等价证明。

## 运行时成本（真实GitHub Runner，不是Jetson）

全部原始数据来自每个实际控制周期记录的\`planning_ms\`。使用最近秩（nearest rank）P95/P99，16个回合的所有实际规划周期合并计算（旧/新方法各**n=2536周期**），不是先对单回合分位数取均值。

| 指标 | 旧全量前瞻 \`two_stage_viability\` | 新严格等价快速前瞻 \`two_stage_viability_fast\` |
|---|---:|---:|
| 周期数 | 2536 | 2536 |
| 平均耗时 | **111.644ms** | **29.367ms** |
| 总体P95 | 167.504ms | 42.914ms |
| 总体P99 | 171.913ms | 50.637ms |
| 全部回合最大耗时 | 185.116ms | 108.076ms |
| 超过100ms控制周期的次数 | 1795 | **2** |
| 超过100ms占比 | 70.781% | **0.079%** |

均值下降\`(111.644-29.367)/111.644≈73.70%\`，对应**3.80倍**的计算吞吐速度比值。改进不是由减少有效安全检查的深度造成；加速主要来自未来布尔存在性搜索提前返回，以及不再探测不可能改变首段选择的剩余高成本候选。

仅2次快速版预算超限，均在\`two_targets/weak_brake/seed0\`回合：\`t≈9.0s\`规划用**108.076ms**；\`t≈9.1s\`规划用**103.342ms**，两周期实际均探测3个前瞻候选。全部12组新种子场景共无一次超过100ms，但样本有限、GitHub共享Runner时间有波动，不能保证全部将来状态都满足周期。

不同压力分层的每控制周期平均耗时（同一Runner）：

| 条件 | 旧ms | 快版ms |
|---|---:|---:|
| 双目标/弱制动/已知种子0,1 | 120.185 | 32.255 |
| 双目标/弱制动/前期种子10,11 | 118.236 | 32.455 |
| 横穿/正常/新种子50,51 | 100.633 | 25.673 |
| 窄路/正常/新种子50,51 | 89.087 | 23.275 |
| 双目标/快速目标/新种子50,51 | 126.252 | 33.093 |

本工作流只是**无计算反馈的离线闭环仿真**：虽然\`Plan.compute_ms\`真实在GitHub Runner上采集，车辆仍严格每100ms接收命令，实际CPU超时没有自动延长物理控制等待，也没有考虑Linux调度/ROS通信/目标跟踪开销。P99低于100ms依然不等于严格实时可用。未来如果要对Jetson进行实测，需要将计算时间和输入接收延迟反馈仿真，量化端到端p99、最坏时延和超期动作策略。

## 完成情况与下一步
