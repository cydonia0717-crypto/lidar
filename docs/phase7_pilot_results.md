# 第七阶段先导结果：终端净空软项无独立收益

来源：[GitHub Actions Run 39208907864](https://github.com/cydonia0717-crypto/lidar/actions/runs/39208907864)，52项单元测试全部通过，12次双目标配对合成仿真完成。所有CSV与图由数值程序实际计算，参见该工作流artifact。

| 工况 | braking_hold 成功/碰撞/超时 | terminal_margin 成功/碰撞/超时 |
|---|---|---|
| two_targets nominal 3种子 | 1/2/0 | 1/2/0 |
| two_targets weak_brake 3种子 | 1/1/1 | 1/2/0 |

完成回合耗时分别为（nominal）17.4s /17.5s；（weak_brake）17.8s /17.6s，但单一工况中均仅有1个成功回合，不能解释为稳健的效率改善。

关键变化：weak_brake/seed0 的braking_hold原来是30秒超时，terminal_margin变成19.4秒碰撞。**碰撞率反而恶化，成功率没有提升。**

推论限制：仅3个种子/工况，理想CV目标与二维圆包络；不能对真实机器人做一般化安全结论，也不能对绝大多数动态环境宣称该软项无效。此先导实验仅表明目前这条固定单阶段候选轨迹和目标函数的组合，不足以消除已复现的双目标死锁。

下一步不应在这些种子上反复调权重直到凑出漂亮结果；应更换具有明确结构差异的规划动作表示，比如有限深度、两阶段速度与前轮转角动作序列，同时保持严格物理约束，并设置留出测试场景。
