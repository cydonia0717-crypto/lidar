# 第八阶段先导实验结果：双阶段候选动作搜索

## 可核查来源

[GitHub Actions Run 39209829487](https://github.com/cydonia0717-crypto/lidar/actions/runs/39209829487)。已通过52项单元测试，运行了历史回归以及两阶段新增配对仿真。数值来自**合成二维理想CV运动仿真**，非实车/雷达数据。

初步对比设置：
- 场景 \`two_targets\`
- 压力 \`nominal\`、\`weak_brake\`
- 种子0、1（每一压力下2对）
- 两种方法 \`braking_hold\` 和 \`two_stage\`
- 车辆加减速、执行延迟、前轮转向约束、道路几何、移动目标状态和停车后6秒风险检查一致；
- 新方法可使用两组速度/前轮转角动作、旧方法只有一组动作，**搜索计算负担与名义候选控制总时长存在差异**，因此也要报告计算耗时并将优化时域差异视为方法的组成部分。

## 日志实际结果

| 条件 | braking_hold 完成/碰撞/超时 | two_stage 完成/碰撞/超时 |
|---|---|---|
| nominal / 2个种子 | 1 / 1 / 0 | 1 / 0 / 1 |
| weak_brake / 2个种子 | 1 / 0 / 1 | 1 / 0 / 1 |

成功回合的通行时间：nominal 从17.4秒降至14.0秒；weak_brake 从17.8秒降至13.4秒。因为每组仅有一个成功回合，不能视为稳定的平均速度改善。

**关键观察：** 正常制动下不再碰撞的那一个种子转成了30秒超时；这说明两阶段方法可能改善短期避碰，却还没有建立充分可靠的长期通过策略。成功次数没有增加。第六、七阶段失败的经验仍然成立：单纯宣称“碰撞减少”会掩盖“避障死锁”和通行任务未完成。

## 计算开销

该方法最多尝试25组第一段动作以及每组至多5种第二段动作，完整验证最多数秒的停后动态目标占据，开销必然高于原25组单动作检查，但**不能凭流程复杂度推断具体耗时**。新的逐案例\`paired_two_stage_effects.csv\`将输出同机同场景\`mean_planning_ms\`与相应差分；完整CPU/Jetson实时性仍需单独实验。

## 后续必要工作

1. 根据超时回合的完整轨迹确定是因为路口附近一直等待、速度/转角候选不足，还是因保守碰撞圆导致窄通道无解；
2. 扩充未参与算法设计的独立随机场景和非匀速目标场景，不能只用前两次已知碰撞种子；
3. 用真正的道路中心线投影/进度及阿克曼矩形车体改进几何与任务完成判据；
4. 对所有同场景方法比较真正完成率、碰撞率、超时、最小净空和计算开销；
5. 尚未接入真实或带噪LiDAR测量、Hungarian目标关联、CV-KF跟踪，不得将这批先导数据表述为真实部署性能或安全保证。
