# 第十四阶段实测结果：30秒时限截断与停车后骑行者侵入

## 来源与实验可靠性

[GitHub Actions Run 39245341166](https://github.com/cydonia0717-crypto/lidar/actions/runs/39245341166) 独立\`Phase14 cutoff and parked intrusion\`工作流**7项针对性测试通过**；使用相同\`two_targets/weak_brake\`场景、种子0和1及\`two_stage_bodyframe\`规划器，完成\`max_time=30/35/40\`共**6次实际闭环仿真**。全部原始证据：[workflow artifact 12183611874](https://github.com/cydonia0717-crypto/lidar/actions/runs/39245341166/artifacts/12183611874)，包含\`horizon_episodes.csv\`、\`horizon_prefix_checks.csv\`、\`horizon_windows.csv\`、六条逐帧\`trajectories/*.csv\`和\`study.json\`。

固定后轴→车体中心假设和物理真值均0.55m、后轴自行车动力学与车辆尺寸不变，制动力0.90m/s²、控制延迟0.25s、候选速度/转角、保守圆形运动目标和道路矩形碰撞检查不变，最终采用严格\`pose_gate\`（车身中心x超过27.4m、横向误差≤0.75m、航向误差≤15°）。**本阶段没有对控制器做任何行为修改。**

## 1. 仿真截止时限是否造成结果重分类

| 场景 | max_time=30s | max_time=35s | max_time=40s |
|---|---|---|---|
| seed0 / weak_brake | 30.00秒超时 | **30.10秒成功** | **30.10秒成功** |
| seed1 / weak_brake | 16.50秒目标碰撞 | 16.50秒目标碰撞 | 16.50秒目标碰撞 |

对seed0，30秒运行的301个位置/姿态/速度/前轮转角状态样本与35秒、40秒两次重跑完全一致，\`max_state_difference=0.0\`、\`missing_baseline_times=0\`、\`prefix_equal=true\`。因此35秒/40秒的完成不是不同的随机世界或运行漂移，而是**同一闭环轨迹延长0.1秒后真正满足了严格终点条件**。

但将30秒设置为35秒只能消除这一次**评估截断错误**，无法修复seed0中间10–22秒间出现的长时间无安全行动、停车和小净空，也不能使seed1免除碰撞。论文的固定成功/超时评价仍应预先规定时间上限，不能在看到结果后随意改阈值并与此前表格混算；应把30s和35s作为“时间预算敏感性”单独呈现。

## 2. seed0：很长时间停车，后段恢复通行

按\`max_time=30\`的真实回合归因：

| 时间 | 自车x位移 | 停车帧比例 | 可行两阶段组合均数/周期 | 紧急不可行控制周期 |
|---|---:|---:|---:|---:|
| 0–5s | +9.18m | 0% | 51.35 | 0 |
| 5–10s | +2.26m | 30% | 19.74 | 0 |
| 10–15s | +0.36m | 82% | 0 | 50 |
| 15–20s | 0m | 100% | 0 | 50 |
| 20–25s | +3.02m | 48% | 57.5 | 20 |
| 25–30s | +11.32m | 0% | 82.96 | 0 |

注意最后一行x位移为窗口内首末**非终止控制帧**之差，不是从25.0到30.0终止末帧的精确距离。

- 规划器从约10.1秒进入\`unsafe_fallback\`状态，直至约22.0秒；第一个阶段无法找到满足全部硬约束的安全候选。
- 15–20秒实际物理目标最小间隙仅约**0.014m**（正数没有发生保守圆几何重叠，但远小于安全margin 0.20m；这期间有明确的不可行退化）。
- 20秒之后目标离开后可行候选恢复，车辆加速并接近终点；第30秒末车身中心x≈27.249m、y≈0.639m、航向误差≈12.08°，严格终点验收只剩纵向约**0.151m**，下一个0.1秒实际达到目标，30.10s才标记成功。
- seed0在静止段的固定位置12秒预测中出现**规划包络侵入**（含安全margin与padding），但没有发生**物理重叠**；更长的停驻检查不必然带来更高任务成功率。

结论：seed0同时暴露**长时等待与评估时限截断**两个现象，不能简单描述为“永久死锁”。

## 3. seed1：无可行备选动作，停车后遭骑行者侵入

- 首次\`unsafe_fallback=1\`约9.7s（整个回合约67个控制周期处于不可行退化）；
- 大约11.7s汽车车速跌至0.1m/s以下。使用固定车位反事实CV预测，此时车辆若继续保持当前姿态，骑行者将于约**4.8秒内**侵入物理保守圆。注意这是事后基于理想合成CV目标真值的诊断，不是传感器实际预报。
- 在12.1s停稳时，固定位置预测显示约**4.4s**之后物理重叠；提前进入规划距离margin+padding包络（预测约3.35s之后）。
- 12.1～14s间\`feasible_pairs=0\`，\`moving_first_action_feasible=0\`，fallback持续为\`emergency_brake\`；车辆已经停稳，无法通过单纯继续刹车改变停车位置。
- 15.2s出现\`unsafe_committed_prefix\`：连已不可撤回的延迟控制前缀都无法满足模型的严格预测安全约束；并非仅仅是备选动作评分不够合理。
- 16.5s真实物理目标圆净空为**−0.004555m**，自车速度0m/s，命中\`cyclist\`；当时距离道路边界仍有较大净空，故属于**动态目标侵入不可恢复的静止车辆位置**，不是道路越界。

这表明：既有6s\`stationary_hold\`预测能力并不等于“安全停车策略有可执行解”。当没有可行候选时，规划器会明确报\`unsafe_fallback\`并请求最大物理制动；这既可能降低自身运动造成的撞击风险，也可能因为停车在横穿目标轨迹上而留下必然几何冲突。**仅延长站立占据时域而不解决可恢复轨迹，很可能增加“无解”状态，不能保证解决这一碰撞。**

## 4. 控制策略开发的下一步（本阶段不修改）

1. **提前防止进入无解控制状态**：在首次仍有可行候选的时刻，比对不同候选第一段动作及其未来安全可行性，考察终端状态附近的道路净空、可行续接集合规模、骑行者穿越时序是否足以将其引导至不会遭未来侵入的可恢复停车位置。重点是“尚可控制时避免进入死角”，不是无法可行后的冒险指令。
2. **严格区分物理安全与模型安全margin**：\`physical_obstacle_gap_m<0\`才算当前保守圆模型的几何重叠，\`gap<0.32m\`代表模型的margin+padding占据限制。过度保守的安全约束也会导致长期无解，需用独立场景校准而不是临时取消。
3. **时间预算作为报告变量**：固定一个主要任务完成期限（例如预先规定35秒），同时报告30/35/40的敏感性结果，不再用30s和35s的成功分母混合比较不同版本算法。
4. **未来要检验递归可行性**：当前滚动时域规划只保证所选假设序列在有限窗口可行，下一次重规划并不保证仍然有安全候选；停后6s占据预测也不构成不变安全集合。需要研究约束化的终端可恢复集或可行性保留机制，不能基于本阶段数据宣称安全保证。
5. 后续如果增加“提前让行/绕行”，应与当前\`two_stage_bodyframe\`在同一合成道路真值、物理偏置、控制延迟、压力场景和严格pose_gate条件下开展新种子配对，完整统计碰撞、超时、道路越界、成功以及计算负担。

## 适用范围

这些结果全部来自**二维合成CV动态目标真值**，既不来自RoboSense激光雷达或Jetson测试，也不包括点云聚类、Hungarian关联、CV-KF误差、行人突然变向、轮胎侧偏、准确车身参考点标定或连续时空无碰撞证明。真实机器人安全不能由此推断。
